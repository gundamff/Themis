# 鉴权与授权基线

## 空认证禁止

管理、数据和执行类接口必须在服务端验证身份与权限。以下情况一律阻断：

- 缺少 token、空 token、格式错误 token 仍返回敏感数据或执行动作。
- 使用缺省主体、匿名主体或仅依赖网络位置获得管理权限。
- 仅通过前端隐藏按钮、路由或参数实现“授权”。
- 认证失败时降级为高权限、共享身份或调试模式。

健康检查只能返回最小存活信息，不得泄露配置、拓扑、版本细节或鉴权状态。

## 敏感接口清单

至少覆盖以下抽象类别：

| 类别 | 接口能力 | 最低授权要求 |
|------|----------|--------------|
| 管理 | 用户、角色、策略、系统配置 | 独立管理权限 + MFA/同等强认证 |
| 数据 | 查询、导出、批量读取、备份恢复 | 数据域和环境级权限，默认拒绝 |
| 执行 | 命令、作业、发布、重启、扩缩容 | 审批绑定的 executor 身份 |
| 凭据 | 创建、读取引用、轮换、吊销 | 不可读取明文，操作全审计 |
| 审计 | 查询、导出、保留策略 | 只读与管理分离，不得删除证据 |

## 检查步骤

1. 从路由、API 描述、消息消费者和管理 UI 后端生成接口清单。
2. 标注数据敏感度、允许主体、动作、环境、租户和审批要求。
3. 对每个接口测试：缺失、空、无效、过期和错误受众的身份材料。
4. 使用低权限主体尝试读取、写入、跨租户、跨环境和批量操作。
5. 验证权限在服务端实施，直接调用后端不能绕过。
6. 确认拒绝事件包含 trace_id、主体摘要、动作和原因，且不泄露秘密。
7. 将结果与 SECURITY.md 第 1、3、5 条及资产清单交叉签署。

预期失败语义：认证缺失返回认证失败；身份有效但权限不足返回授权失败；两者均不得执行副作用。

## 最小授权模型

```yaml
resource: <abstract-resource>
action: read|write|execute|admin
allowed_principals: [<role>]
environment: <scope>
tenant: <scope>
approval_required: true|false
default: deny
```

observer 只能使用只读 profile；executor 的写权限必须限时、限资源、绑定审批，禁止单一实例拥有全网超级权限。

## 回归项

- [ ] 缺失、空、无效、过期身份均失败
- [ ] 前端隐藏不作为授权证据
- [ ] 低权限主体不能写入或跨域访问
- [ ] 批量接口与单项接口执行相同策略
- [ ] 新接口默认拒绝，已纳入敏感接口清单
- [ ] observer/executor 身份和凭据保持分离
- [ ] 拒绝与审批事件可审计，防护不可静默关闭
