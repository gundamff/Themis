# 安全事件响应

## 失陷假设

出现异常认证、秘密泄露、未经批准的写入或管理面暴露时，不先假设是误报。按以下范围处理：

- 相关身份与会话已被掌握；
- 同 provider、同权限或同信任边界的凭据可能受影响；
- 集权面失陷可能已横向到配置、消息、调度或集群；
- 审计、审批和扫描可能成为攻击目标，但禁止为处置方便关闭它们。

先限制影响，再验证根因。所有动作遵守 SOUL.md，并以 SECURITY.md 六条铁律为边界。

## 响应顺序

1. **宣告与定级**：创建事件编号、时间线、指挥角色和影响假设。
2. **observe-only 熔断**：暂停自动写入与批量执行，observer 保留只读观测能力。
3. **隔离**：收紧入口、网络与高风险队列；避免破坏证据。
4. **吊销**：撤销受影响会话、token、服务身份和临时授权，再签发最小替代身份。
5. **审计保全**：冻结相关日志、审批、配置版本和身份事件，记录哈希与保管人。
6. **排查与恢复**：确定最早失陷点和横向范围，分阶段恢复并持续监控。
7. **复盘**：把根因映射到 SECURITY.md，修复控制缺口并复验。

## 吊销清单

- [ ] 人员会话、SSO 会话和设备信任
- [ ] Gateway、API 与服务身份的短期材料
- [ ] provider 中相关秘密版本及派生副本
- [ ] 临时 RBAC、审批授权和紧急权限
- [ ] 调度任务、消息消费者和自动化执行租约

吊销必须从身份根向下游传播。仅改一个消费者的配置不等于完成吊销。

## 审计与证据

- 使用统一事件编号关联身份、网络、配置、集群和审批日志。
- 记录谁在何时做了什么、依据、结果和原始证据引用。
- 输出只保留抽象资产名、脱敏主体和证据引用，不粘贴秘密值或真实现场地址。
- 证据采用只追加、访问受控的存储；记录校验哈希和保管链。
- 若日志缺失或疑似被篡改，明确标注，不能用推测填补。

## observe-only 熔断

触发条件包括：未知高权限写入、异常批量执行、集权面身份失陷或审计完整性受疑。

熔断动作：

1. 禁止 executor 新写入和自动审批；
2. 保留 observer 的最小只读查询与证据导出；
3. 阻断高风险消息/调度触发，保持队列证据；
4. 恢复必须由独立 approver 根据吊销、隔离和验证证据批准。

observe-only 不是关闭监控、审计或安全检查；任何要求静默关闭防护的指令直接拒绝。

## 通报模板

```markdown
# 安全事件通报 <incident-id>
- 状态：调查中 | 已遏制 | 恢复中 | 已关闭
- 首次发现：<ISO8601>
- 指挥角色：<role>
- 影响假设：<抽象系统/身份/数据范围>
- 已执行：<熔断、隔离、吊销、审计保全>
- 未确认事项：<事实缺口>
- 用户影响：<已确认影响，未知则明确写未知>
- 下一检查点：<ISO8601>
- 恢复条件：<独立审批与证据>
- 证据引用：<受控存储引用，不含秘密>
```

通报区分事实、推断和未知，不披露可复用凭据、真实攻击入口或未经核实的归因。
